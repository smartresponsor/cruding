= Cruding

Universal CRUD route processor and capability-resolution bundle for Symfony host applications.

== Responsibility

Cruding owns CRUD route processing, resource-bound surface route parsing, entity/form resolution, neutral browser surface payloads, API responders, mutation guards, and minimal diagnostic fallback rendering. Resource-bound relation/object-meta/frontend surface routes belong to Cruding when they can be expressed through the resource/subject/surface/action grammar. Cruding still does not own platform menus, external callbacks, webhooks, health/metrics endpoints, or local application shell CSS.

== Bundle loading

`CrudingExtension` loads `config/services.yaml` from the bundle and registers `templates/` as the `@Cruding` Twig namespace. Host applications may configure these options under the `cruding` extension key:

* `resource_path_requirement`
* `capability_map`
* `entity_class_alias_map`
* `form_type_map`

The shipped defaults keep the component usable as a CRUD route processor without requiring neighbour-component hardcode.


== Resource-surface routes

Cruding also exposes a read-oriented resource-surface controller for routes that are not classic admin CRUD, but are still resource-bound. The route path is the declaration:

[source,text]
----
/{resource}/{subject}/{surface}
/{resource}/{subject}/{surface}/{action}
/{resource}/{subject}/{surface}/{item}/{action}
----

Examples:

[source,text]
----
/vendor/acme-inc/compliance/briefing
/vendor/acme-inc/document/w9-form/preview
----

The controller parses the route template into a `CrudRouteContext`, locates a producer provider by convention, and returns only `CrudSurfaceContract`. Producer providers implement `CrudSurfaceProviderInterface` and return a location-based payload. They must not render Twig or return Symfony `Response`/`JsonResponse`.

If no producer provider exists, the surface controller falls back only to generic read operations (`index`, `detail/show/view`). Mutation routes remain on the existing CRUD controllers.

See `docs/cruding/cruding-resource-surface-routes.md`.

== Viewing / Interfacing resource surface rendering

For resource-surface routes, Cruding is the producer-side route-token and payload owner only. It returns `CrudSurfaceContract`; it does not own the runtime Twig lookup, final fallback chain, or HTML response decision. Viewing owns the render boundary and may use Interfacing as a passive template tree when available. The canonical runtime fallback is:

. `@Interfacing/<surface-or-resource>/index.html.twig`
. `@Interfacing/index.html.twig`
. `@<Component>/index.html.twig`
. `@Viewing/view/index.html.twig`

Any `templateCandidates` exposed by `CrudRouteContext` are diagnostic folder/index hints for debug commands only. They are not a render contract and must not reintroduce operation-based Twig files such as `<operation>.html.twig`.

== Routing/template contract

Cruding declares its reusable resource-path route requirement through `cruding.resource_path_requirement`. The default requirement reserves only CRUD/meta operation path segments (`new`, `edit`, `delete`, `audit`, `visibility`, `attach`, `detach`) so the processor does not carry hard-coded neighbour or frontend-section exclusions such as profile/cart/vendor-specific rules. Host applications should mount Cruding where generic resource processing belongs.

Incoming `resourcePath` values are normalized before entity lookup, route generation, and surface rendering. Underscore aliases become hyphenated paths, duplicate slashes collapse, and paths are lowercased.


== Dependency policy

Cruding must remain installable as a CRUD route processor without a hard Composer dependency on an Interfacing package. The integration boundary is the Twig namespace contract (`@Interfacing/...`) exposed by the host application when Interfacing is installed.

For local validation use:

[source,powershell]
----
composer update -W
composer validate --strict
composer dump-autoload
composer canon:cruding
.\vendor\bin\phpunit
----


== W8 dependency/test seal

Cruding intentionally keeps `composer.lock` as a local development artifact only. The repository ignores `/composer.lock` and `/vendor/`, while `composer.json` declares the runtime packages needed by the CRUD route processor, including Symfony Form support for optional host-provided form types.
